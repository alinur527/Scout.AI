# CV data flow and supported measurement

Current model selection: `CV_DETECTOR_POLICY=auto` routes videos with width>=1920 and width/height>=3 to local YOLO11n person weights; other shapes retain configured base weights, by default YOLO11n-pose. Explicit pose/person policies allow rollback and experiments. Both feed the same VideoProcessor/BoT-SORT/timing/camera/report pipeline. Person detection uses bbox bottom centre, with report provenance and a warning about approximate feet. Optional pose uses the existing ankle/fallback policy. No production grass filter, tiling, stitching or physical compensation is enabled. The quantitative selection and broadcast regressions are in [SMALL_PLAYER_EXPERIMENTS.md](SMALL_PLAYER_EXPERIMENTS.md).

Upload validation reads decoding/FPS/frame-count/resolution; API creates a durable detection job. One worker streams every frame through the selected local COCO detector and original BoT-SORT (.3 high/new, .1 low, buffer90, match.8, sparse optical-flow GMC, no ReID). Detector class0 is COCO person, conf.3 / NMS IoU.5. Native maximum dimension rounded to32 is clipped640–1280 for inference, preserving HD detail without expensive low-resolution upscaling. GMC supports association; it does not make a fixed homography valid for a moving camera.

VideoProcessor returns frame index, decoder timestamp, frame, tracked detections, ground points. Keypoints15/16 with confidence≥.4 and finite coordinates are averaged; missing ankles fall back to bbox bottom centre. This unsmoothed image policy was retained after experiments. Decoder PTS must be finite, nonnegative and strictly increasing; nominal-FPS fallback is marked unreliable for physical metrics. No inference frame skipping. Saving samples is capped at10Hz per ID; frame coverage counts full decoded-frame observations separately. First valid crop per ID remains the gallery thumbnail; it may be poor or depict a referee/staff member.

Detection stores sampled tracks, thumbnails, previews, full frame counts, timestamp reliability and a conservative background-camera summary; source upload is then deleted. Galleries require ≥2 sampled observations. The report stage uses only persisted data, so refresh/restart/selection do not depend on a source file. Maximum250 fragmented IDs, video duration/frame/resolution limits and existing queue/recovery behavior remain.

Physical metrics require valid manual rectangle geometry, explicit uploader stationary-camera confirmation, `no_motion_detected` by the background monitor and reliable PTS. Unknown/moving cameras or missing confirmation produce an image-space report with null distance/speed/sprints. The motion monitor is a veto, not a calibrated camera classifier or motion compensation. It is tested with synthetic patterns and this small dataset; no measured false-positive/negative rate.

Calibrated points outside the chosen polygon break continuity. Invalid values, gaps>.5s and raw jumps>45km/h start fresh segments. Time-aware EMA tau.15s smooths field positions; distance/speed sum within segments. Speed>21km/h for≥.6s counts one sprint event until it returns below threshold or continuity breaks. Report `movement_segments` prevents the UI joining gaps; flat `movement` remains for old clients. Physical accuracy is always explicitly not validated.

Technical `observed_frame_coverage`=selected-ID frames/decoded frames; `trajectory_segments` counts retained continuous pieces. These are visibility/continuity indicators, never an accuracy percentage. UI uses existing Segoe UI/Bahnschrift, night#080d19/navy#101a2d/surface#17233a/violet#a99aff/cyan#62e6eb/ink#eef4ff tokens; warnings and left-aligned provenance sit beside the image map. Design review retained the established layout and removed any need for a new score/card system. Screenshot review covers desktop/tablet/mobile.

The offline harness can run original parameters or the actual production processor, capture pre-tracker detections, score frozen labels and export JSON/CSV/annotated frames. ML validation is opt-in locally. CI covers deterministic math, homography, camera patterns, malformed/missing pose inputs, mocked detections/decoding and API/demo browser behavior without ML weights. See [FOOTBALL_VALIDATION.md](FOOTBALL_VALIDATION.md) for quantitative results and unresolved failures.
